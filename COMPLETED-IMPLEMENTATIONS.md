# Completed Implementations — Pinned Projects Extension

Historical context and proven patterns for this project.

## Extension Features

- Pin/unpin workspace root folders via Explorer context menu (**Pin Project to Top** / **Unpin Project**).
- Order persisted per workspace (`workspaceState`); reorder applied via `workspace.updateWorkspaceFolders()`.
- Command **Pinned Projects: Apply Pinned Order** to reapply after adding folders.
- Activation on startup to restore order when opening a workspace.

## Build & Release

- **CI**: `.github/workflows/build.yml` runs on tag push `v*`. Steps: checkout, Node 20, npm ci, compile, lint, generate icon, package VSIX, upload artifact; publish job runs `ovsx publish` with `OPEN_VSX_TOKEN`.
- **Icon**: 128×128 PNG generated by `npm run generate-icon` (script in `scripts/generate-icon.js`, uses `pngjs`). SVG source: `icon.svg` (map-pin teardrop).
- **Versioning**: 3-tag rule — maintain `vX.X.X`, `vX.X`, and `vX` (and optionally `latest`) so minor/major tags point to latest release in that line.

## Documentation Layout

- Root: README.md (marketplace-facing), CHANGELOG.md, LICENSE, SECURITY.md (if added).
- `doc/`: installing.md, building.md, publishing.md.

## Security

- Snyk: run `snyk_code_scan` and `snyk_sca_scan` on the project path before merging; fix critical/high.

## Decisions

- Open VSX for publishing (Cursor); repository and license in package.json for vsce/marketplace.
- Self-hosted runners for GitHub Actions; Node 20 in both build and publish jobs.
- TypeScript + ESLint with @typescript-eslint for linting .ts source.
